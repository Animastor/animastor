# TXT Import: Structure Detection v2 (Candidates → LLM → Chapter Map)

> Статус: утверждено к реализации. Заменяет подход «окно → глава» из v1.

## 1. Проблема v1 (итоги аудита `ba_1785985491053`)

Текущий импорт построен инвертированно: окна нарезаются по количеству символов,
и из окон «выращиваются» главы. Реальные границы книги (`splitIntoChapters`,
regex) вычисляются, но не управляют структурой. Последствия (подтверждены
трассировкой кода и фактическими JSON):

| Проблема | Причина |
|---|---|
| Название не определяется | Первая строка не входит ни в одну главу; окно 0 начинается внутри главы 1 — заголовок не доходит ни до анализа структуры, ни до сцен |
| Пролог игнорируется | `prologueRe` требует строку ровно «Пролог»; строка «Пролог. Мир на переломе эпох» не матчится, текст пролога теряется |
| Глава 1 определяется криво | Заголовок «Глава 1» срезается из окна — LLM «не видит» главу 1 |
| Остальные главы сливаются | Книга умещается в одно окно → все сцены в один файл главы; `structure.chapters` LLM сохраняется как метаданные, но не влияет на структуру |
| Обложка с названием из имени файла | `createCoverChapter` фолбэчит на `bookMeta.title` (= имя файла) |

## 2. Архитектура v2: разделение ответственности

```
┌─────────────────────────┐   ┌──────────────────────────┐
│ Программа (детерм.)     │   │ LLM (семантика)          │
│ structure-detector.js   │   │ structure.md v2          │
│                         │   │                          │
│ ищет КАНДИДАТОВ:        │   │ классифицирует:          │
│  - короткая строка перед│   │  «Это название книги?»   │
│    большим абзацем      │   │  «Это пролог?»           │
│  - строка между пустыми │   │  «Это глава?»            │
│    строками             │   │  «Это обычный заголовок  │
│  - первая строка        │   │   внутри текста?»        │
│  - ALL-CAPS / номер /   │   │  + confidence 0..1       │
│    римская цифра        │   │                          │
│  - regex-слова          │   │ «найти то, что есть»,    │
│    (Глава/Chapter/…)    │   │ НЕ «построить роман»     │
│    только как подсказка │   │                          │
└───────────┬─────────────┘   └────────────┬─────────────┘
            │  кандидаты (id + текст +     │ решения по id
            │  контекст, offset'ы)          │ (никаких выдуманных offset'ов)
            ▼                              ▼
      ┌─────────────────────────────────────────┐
      │ CHAPTER MAP (канон): title, author,      │
      │ segments[{type,label,title,number,       │
      │ startOffset,endOffset}]                  │
      │ + has_prologue, parts                    │
      └─────────────────┬───────────────────────┘
                        ▼
      ┌─────────────────────────────────────────┐
      │ Пайплайн: окна НЕ пересекают границы     │
      │ глав; каждая глава → отдельный JSON;     │
      │ типографическая сцена в начале главы;    │
      │ обложка — только если есть название      │
      └─────────────────────────────────────────┘
```

Правила:
- **Программа не принимает решений.** RegEx и словари ключевых слов — только
  источники гипотез и бусты уверенности (мультиязычность достигается тем, что
  решение принимает LLM).
- **LLM не выдумывает смещения.** Все привязки к тексту идут через
  `candidate_id` (или точное совпадение строки в исходнике). Не нашлось — решение
  отбрасывается.
- **Универсальность.** Структура не навязывается: роман, рассказ, стихотворение,
  несколько предложений, отрывок — всё это корректные входы. Отсутствие автора,
  названия, пролога или глав — нормальная ситуация, не ошибка.

## 3. Формат кандидата

```js
{
  id: 'c12',               // якорь для LLM
  lineIndex: 41,           // индекс в lines[]
  startOffset, endOffset,  // смещения в sourceText
  text: 'Глава 2. Первый полёт',
  length, wordCount,
  firstNonEmpty: false,    // первая непустая строка документа
  inHeadBlock: false,      // первые ~8 непустых строк (зона название/автор)
  blankLinesBefore: 1, blankLinesAfter: 1,
  standalone: true,        // пустая строка сверху И снизу (или край документа)
  allCaps: false,
  sentencePunctuation: false,  // заканчивается .!?… или содержит ,;:
  followedByLongParagraph: true,
  nextParagraphPreview: 'Пока большинство людей спорило о будущем…',
  separatorAbove: false, separatorBelow: false,
  keyword: 'chapter',      // из словаря гипотез | null
  numbered: true, romanNumeral: false,
  prefixDash: false,       // строка-реплика «— …»
  headingLikelihood: 0.83  // оценка программы (не решение!)
}
```

Кандидатом считается непустая строка ≤ 120 символов с признаками
«подозрительности»; сильные кандидаты (`headingLikelihood ≥ 0.55` или keyword)
становятся потенциальными границами глав.

## 4. Формат карты глав (chapter map)

```js
{
  title:  { text: 'За пределами алгоритмов', source: 'ai' | 'detect' } | null,
  author: { text: null, source } | null,
  hasPrologue: true, hasEpilogue: false,
  parts: [{ name: 'ЧАСТЬ ПЕРВАЯ', order: 1 }],
  segments: [
    { type: 'prologue', label: 'Пролог', title: 'Мир на переломе эпох',
      number: null, headerLine: 'Пролог. Мир на переломе эпох',
      startOffset: 26, endOffset: 772, source: 'ai' },
    { type: 'chapter', label: 'Глава', title: 'Земля',
      number: 1, headerLine: 'Глава 1. Земля',
      startOffset: 773, endOffset: 1313, source: 'detect' },
    // …
  ],
}
```

- `type`: `prologue | chapter | epilogue | introduction | preface | afterword |
  appendix | part | poem | body`. `body`/`poem` — неструктурированный текст
  (типографическая сцена-заставка НЕ создаётся).
- `label` — слово из исходника («Глава», «Chapter», «Пролог»…), чтобы заставка
  была на языке книги.
- `startOffset` — начало строки-заголовка (заголовок остаётся внутри текста
  сегмента, как в v1; `findNarrativeStartOffset` срезает его для окна).
- Пролог = индекс 0, главы = 1..N (фронтенд уже так читает). Обложка — служебная
  глава без `chapter_index`.

## 5. Детерминированная карта (fallback без LLM)

`buildDeterministicMap(sourceText)`:
1. Собрать кандидатов.
2. Название/автор (зона титула, см. ниже).
3. Границы: сильные кандидаты вне зоны названия, не реплики («— …»).
4. Склейка многострочных заголовков: «Глава 1» + (до 2 пустых строк) + «ЗАГОЛОВОК» —
   одна граница; ALL-CAPS строка является заголовком даже с пунктуацией внутри
   («ШИЗОФРЕНИЯ, КАК И БЫЛО СКАЗАНО», «ПОРА! ПОРА!»).
5. Номер главы: `Глава 1.`, `Chapter 12:`, римские цифры (`extractNumber`).
6. Если границ нет → один сегмент `body` со всем текстом (минус название/автор).

### Зона титула: три раскладки

| Раскладка | Пример | Признаки |
|---|---|---|
| `Название. Автор.` одной строкой | «За пределами алгоритмов. С.А. Хабаров.» | `splitTitleAuthor` по последнему разделителю `. ` / `—` перед именем-шаблоном |
| `Название ФИО` без разделителя | «За пределами алгоритмов С. А. Хабаров» | `trailingFullNameIndex`: ФИО в КОНЦЕ строки, есть инициалы, заголовочная часть ≥ 3 слов (иначе «Звали его Д. И. Иванов» не сплитится); ФИО внутри текста названия («Жизнь Хабарова») — часть названия |
| Инвертированный титул | «Михаил Афанасиевич Булгаков»\n«Мастер и Маргарита» | автор первой строкой: полное ФИО ≥ 3 слов БЕЗ инициалов, ниже короткая не-имя-строка = название |

### Surname-frequency check (автор vs персонаж)

После любого из трёх разборов фамилия из кандидата-автора прогоняется по
нарративу: `extractSurname` (последнее слово-не-инициал) + `countSurnameInText`
(с учётом русских склонений: Хабаров/Хабарова/Хабаровым; регистрочувствительно —
в прозе имена пишутся с заглавной). Фамилия встречается в тексте ПОСЛЕ титульной
строки ≥ 2 раз → это ПЕРСОНАЖ, не автор («Жизнь Хабарова», где Хабаров — герой):
автор отбрасывается, чистый заголовок сохраняется. 0 вхождений → автор
подтверждается. Работает и в детерминированном пути, и в LLM-мерже
(`sanitizeStructure`), где это часть антигаллюцинационного слоя: агент сказал
«есть ФИО» — программа проверила текст.

## 5а. Шаблонное обучение глав + постер-фильтр

Если первые 2+ сильные границы — главы вида «Глава N» (`learnKeywordTemplate`,
переиспользует `extractNumber`, поэтому понимает и римские цифры), остальные
главы книги обязаны следовать ТОМУ ЖЕ шаблону — это «обучение по стилю»: стиль
первых распознанных глав (есть ли слово «Глава», как отделён заголовок, ALL-CAPS
ли он) применяется к остальным.

`applyKeywordTemplate(merged, sourceText)` отбрасывает сильные строки БЕЗ
структурного ключевого слова — это декоративные афиши внутри глав (постер
«ПРОФЕССОР ВОЛАНД» в «Мастере и Маргарите»), а не границы. Отбрасывание ТОЧЕЧНОЕ:

- **(a) приклеена** в ≤ 4 строки к предыдущему keyword-заголовку;
- **(b) многострочный постер-блок:** следующая строка — одна короткая (≤ 60 симв.)
  без точки (продолжение афиши «Сеансы черной магии с полным ее разоблачением»,
  часто в обычном регистре), а за ней — длинная проза (≥ 120 симв.). Признак
  нужен потому, что в реальной книге афиша стоит на 28 строк ниже «Глава 10» —
  близости недостаточно.

Дальняя ненумерованная секция («ВМЕСТО ЭПИЛОГА», интерлюдия, раздел в смешанной
книге) НЕ отбрасывается — расстояние от keyword-заголовка большое, структура не
теряется. Книги без слова «Глава» (только ALL-CAPS заголовки) шаблон не
активируют — поведение прежнее.

### Прочие детерминированные правила

- **«ЧАСТЬ ПЕРВАЯ/ВТОРАЯ» — декоративное деление:** остаётся точкой разбиения
  текста и упоминается в `parts`, но НЕ создаёт главу-сегмент (заголовок части
  выпадает из контента).
- **Диапазон годов** («1929 — 1940») в конце книги — колофонные данные, никогда
  не глава (`DATE_RANGE_RE`).
- **Штраф пунктуации для ALL-CAPS строк смягчён** (−0.15 вместо −0.4): ALL-CAPS —
  классический «кричащий» заголовок главы русских изданий, иначе заголовки с `!`/`,`
  вплотную к «Глава N» не дотягивали до порога strong (0.55).

## 6. LLM-шаг (structure.md v2)

Один вызов. На вход: топ документа (первые ~15 строк с контекстом) + список
кандидатов (`id`, текст, `nextParagraphPreview`). На выходе JSON:

```json
{
  "title":       { "text": "…", "candidate_id": "c1", "confidence": 0.92 },
  "author":      { "text": "…", "candidate_id": "c2", "confidence": 0.7 },
  "has_prologue": true, "has_epilogue": false,
  "parts":       [{ "name": "ЧАСТЬ ПЕРВАЯ", "order": 1 }],
  "elements": [
    { "candidate_id": "c5", "kind": "prologue", "title": "Мир на переломе эпох",
      "number": null, "confidence": 0.95 },
    { "candidate_id": "c8", "kind": "chapter", "title": "Земля",
      "number": 1, "confidence": 0.98 },
    { "candidate_id": "c9", "kind": "reject", "confidence": 0.9 }
  ],
  "country": null, "epoch": null
}
```

- `kind`: `prologue | chapter | part | epilogue | introduction | preface |
  afterword | appendix | poem | heading | reject`.
- Элемент ссылается ТОЛЬКО на `candidate_id` (или точный `line_text` из
  исходника). Нет якоря → элемент игнорируется (LLM не выдумывает offset'ы).
- `confidence < 0.5` → трактуется как `reject`.
- Инструкция модели: «Элемента нет — спокойно верни пусто/null, не придумывай».
  Это и есть принцип «найти то, что действительно есть».

`mergeAiDecisions`: карта v2 = детерминированная карта + решения LLM
(добавление/удаление границ по lineIndex, уточнение названий/номеров/типов,
title/author). Валидация: каждая граница — реальная строка исходника.

### Антигаллюцинационный слой (`sanitizeStructure`)

Перед применением ответ LLM прогоняется через детерминированный валидатор.
RegEx здесь НЕ решает, что такое строка — он только **запрещает невозможное**:

- **Якорь**: элемент обязан ссылаться на существующий `candidate_id` (или
  `line_text`, найденный в исходнике дословно). Нет якоря → выдумка, элемент
  отбрасывается. LLM физически не может ввести несуществующий offset.
- **Автор**: 2–4 токена, каждое — слово с заглавной или инициал ("С.А."),
  без цифр/URL; длина ≤ 60; минимум одно полноценное слово (фамилия).
  "999 не существует" или целое предложение → не автор.
- **Название/заголовок главы**: длина 1–120, ≤ 14 слов; если длиннее 60 —
  без `,;:` (иначе это предложение, а не название).
- **Номер главы**: целое 1–999.
- **Консистентность**: автор ≠ название; два элемента на один кандидат —
  побеждает последний; `confidence < 0.5` = `reject`.
- **Отбракованный элемент** (reject/не прошёл проверку) убирает границу —
  текст остаётся нарративом предыдущего сегмента.

Заголовок и автор на ОДНОЙ строке (`За пределами алгоритмов. С.А. Хабаров.`)
разбираются детерминированно через `splitTitleAuthor` (последний разделитель
". "/"— " перед именем-шаблоном) — и на LLM-шаге, и в fallback.

## 7. Интеграция в пайплайн

| Файл | Изменение |
|---|---|
| `services/structure-detector.js` (new) | кандидаты + детерминированная карта + слияние решений LLM |
| `book/lazy-book/parser.js` | `splitIntoChapters` → детерминированная карта (пролог = index 0, корректные границы); прежний контракт массива сохранён |
| `book/lazy-book/create.js` | обложка только при реальном названии; заставка «Пролог/…»; заставка из карты; `body` без заставки |
| `book/lazy-book/chapter-utils.js` | `buildSegmentIntro()` — типографическая сцена из сегмента |
| `services/agent/pipeline-steps.js` | `stepAnalyzeStructure` → классификация кандидатов (старый вызов остаётся совместимым) |
| `services/agent/pipeline-runner.js` | `getWindowText` — окно не пересекает границу главы; опциональный `chapterMap` |
| `services/agent/bootstrap.js` | структура считается ДО нарезки окон; AI-уточнённая карта персистится в `window_data.structure.segments` |
| `ai/rules/structure.md` | v2: классификация без навязывания |

Поток импорта v2:
1. `createDraftBook` (как сейчас).
2. `extractCandidates(sourceText)` + `stepAnalyzeStructure` → `structure`
   (title/author/parts/segments). При ошибке LLM — детерминированная карта.
3. `getWindowText(..., { chapterMap })` — окно 0 = первый сегмент (обычно пролог),
   окно не выходит за конец сегмента.
4. `runPipeline` создаёт сцены окна; `createFromAnalysis`/`appendToBook`
   материализуют главу по `chapterIndex` (= индекс сегмента): заголовок, тип
   (`prologue`/`chapter`/…), типографическая заставка, обложка из `structure.title`.
5. `bootstrapNextWindow` берёт offset из сохранённых сцен, продолжает в следующем
   сегменте карты (карта — из `window_data.structure.segments`).

## 8. Универсальность (таблица приёмки)

| Вход | Ожидание |
|---|---|
| Название + пролог + главы (тест) | cover(название) + пролог(0) + главы 1..3, у каждой типографическая сцена |
| Название и сразу текст | cover(название) + один сегмент `chapter` без номера… нет — `body` с текстом, без «Глава 1» |
| Только текст, без названия | без cover; один сегмент `body`; сцены с первых предложений |
| Название и автор | cover(автор + название) |
| Автор без названия | автор в метаданных, без cover |
| Стихотворение без заголовков | один сегмент `body`/`poem`, без заставки «Глава 1» |
| Несколько предложений | один сегмент `body` |
| Большой роман | главы по карте; большие главы нарезаются окнами с append в тот же файл |
| Роман с «Глава N» + ALL-CAPS заголовками, частями и афишами (проверено: «Мастер и Маргарита», 8093 строки) | инвертированный титул (автор+название), 32 главы + эпилог, части декоративные, афиша «ПРОФЕССОР ВОЛАНД» и диапазон годов «1929 — 1940» отброшены, заголовки с `,`/`!` склеены |

## 9. Масштабирование

Тот же механизм (кандидат → классификация) позже покрывает без изменения
программной части: эпилоги, предисловия, послесловия, приложения, стихотворные
вставки (`poem`), сноски, части (`part`). Достаточно расширить `kind` в
`structure.md` и добавить тип заставки — детектор кандидатов не меняется.
