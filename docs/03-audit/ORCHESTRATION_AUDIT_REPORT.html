2. Две state machine

✅ Верный дизайн

Разделение на per-asset (высокоуровневый статус для scheduler) и audio-orch (детальный пайплайн для watchdogs) — правильная абстракция. Ниже — что уже проверено по коду.

Asset State Machine (state.js)

startScene() setSceneGenerating() completeStage() NEW ──────────→ PENDING ───────────────→ GENERATING ────────→ READY ↘ FAILED ──→ PENDING (re-dispatch) setSceneGenerating() DIRTY ────────────→ PENDING (regenerate)

Key: animastor:scene-assets-state:{bookId}:{chapterId}:{sceneId} → { audio, image, video }

Audio-Orch State Machine (audio-orchestrator.js)

initPlaceholderReady() setGenerating() setWaitingChunks() NEW ─────────────────────→ PLACEHOLDER_READY ──────────→ GENERATING ──────────→ WAITING_CHUNKS ──→ MERGING ──→ DONE completeChunk() ↘ FAILED failWaitingScene() / watchdog FAILED ──→ GENERATING (scheduler re-dispatch) FAILED ──→ WAITING_CHUNKS (completeChunk, late chunk recovery)

Key: animastor:audio-orch:{bookId}:{chapterId}:{sceneId} → { phase, expected_count, chunks_received, last_chunk_at, started_at, build_id }

Инвариант (всегда true)

audio-orch.phase == DONE ⇔ asset.audio == READY audio-orch.phase == FAILED ⇒ asset.audio ∈ {FAILED, PENDING} audio-orch.phase ∈ {WAITING_CHUNKS, MERGING, GENERATING} ⇒ asset.audio == GENERATING

Проверяется в reconcileCycle → checkAudioOrchInvariants().

✅ Инварианты подтверждены кодом

completeStage('audio') в orchestrator.js:161-184 пишет READY только после version gate и audioOrch.completeMerge() → DONE. failStage('audio') → FAILED синхронно. markDirtyScene('audio') → deleteState при DONE.

3. Единый фасад orchestrator.js M5 ✅

Единственный модуль, который пишет lifecycle-состояние. Никто не вызывает state.setAssetState() или audioOrch.*() напрямую — только через фасад. Исключение: unsafe* методы для restore/debug, явно помеченные.

setSceneGenerating → GENERATING если DONE → skip; иначе → GENERATING scene-orchestrator
setScenePlaceholder → PLACEHOLDER — scene-window
completeStage → READY → DONE audioOrch.completeChunk, task-handler
failStage → FAILED → PENDING → FAILED /gpu/task/error, watchdog, recovery
markDirtyScene → DIRTY если DONE → deleteState reconciliation, resetScenes

4. Dispatch Engine — полный пайплайн

Dispatch-engine реализует полный конвейер перед отправкой job в GPU. Fairness-engine удалён в S1 (618 строк мёртвого кода).

dispatchStage(): 1. Force pre-clear (если force=true) 2. Circuit breaker check (5 failures → open → 30s cooldown) 3. Duplicate/stale lease check 4. Quota acquisition (Lua atomic: GET+INCR) 5. Retry budget check (per-scene INCR + TTL) 6. Lease acquisition (NX + TTL: audio 15min, image 20min, video 30min) 7. Set dispatch metadata 8. Journal event 9. Call orchestrator.dispatchStage() 10. Start lease renewal timer (только после dispatched:true)

Идемпотентная финализация

finalizeDispatch(outcome): success → recordSuccess + circuitBreaker.recordSuccess НЕ расходует retry budget failure → recordFailure + circuitBreaker.recordFailure consumeRetryBudget ровно 1× cancelled→ без circuit breaker, без retry budget DISPATCH_CANCELLED
✅ Проверено по коду

completeStage НЕ пишет READY без handler.ok === true + version gate. failStage НЕ пишет recordSuccess. execute*Dispatch возвращает честный { dispatched, jobs, reason } — lease/quota освобождаются при dispatched:false. Renewal стартует только после dispatched:true.

7. Regeneration System R0-R19 ✅

Система частичной/полной перегенерации контента после редактирования vbook. Все 20 задач выполнены.

Протокол

Dependency Graph

SceneText ├──► Audio (mp3) — отдельно, параллельно Image │ └──► UnitText ──► ImagePrompt ──► Image (png) │ └──► Video (mp4 без звука) Cross-cutting: Character.appearance ──► Image Character.voice ──► Audio Location ──► Image Video ✚ Audio ──► FinalVideo (mux на экспорте, не GPU)

8. Call Flows

8.1 Штатная генерация аудио

Scheduler tick → attemptDispatch() → shouldScheduleAssets(): asset=PENDING → stages=['audio'] → dispatchStage('audio') → acquireLease(), acquireQuota() → scene-orchestrator.executeAudioDispatch() └─ orchestrator.setSceneGenerating('audio') → asset.audio = GENERATING → audioOrch.setGenerating() (PLACEHOLDER_READY → GENERATING) → audioOrch.setWaitingChunks() → audio.generateSceneAudio() → GPU hub (9 chunks) → return { dispatched: true } Chunk 0009 arrives → /gpu/task/result → handleTaskResult() → save to disk → audioOrch.completeChunk() → WAITING_CHUNKS → MERGING (all 9 present) → ffmpeg merge → MERGING → DONE → orchestrator.completeStage('audio') → handleAudioCompleted() → version gate (PG) → asset.audio = READY (синхронно с audio-orch DONE) → finalizeDispatch(success)

8.2 Watchdog (timeout)

reconcileCycle → checkStalledAudioScenes() → audioOrch WAITING_CHUNKS, last_chunk_at + 5min < now → audioOrch.failWaitingScene() └─ orchestrator.failStage('audio') → asset.audio = FAILED + audio-orch = FAILED (синхронно) → finalizeDispatch(failure) Scheduler tick (next) → asset.audio = FAILED → PENDING (re-dispatch) → dispatchStage('audio') └─ orchestrator.setSceneGenerating('audio') → audio-orch FAILED → GENERATING (valid)

8.3 Regenerate

User edits → POST /regenerate → orchestrator.resetScenes() → orchestrator.markDirtyScene('audio') → audio-orch DONE? → deleteState → asset.audio = DIRTY → scheduler.addSceneToActiveIndex() Scheduler tick → asset.audio = DIRTY → stages=['audio'] → dispatchStage('audio') → orchestrator.setSceneGenerating('audio') → audio-orch: no state → initPlaceholderReady → setGenerating → asset.audio = GENERATING → dispatch to GPU

8.4 Stale recovery (WAITING_CHUNKS → reset)

После рестарта: audio-orch WAITING_CHUNKS (старая генерация) → Scheduler видит asset.audio = GENERATING → dispatchStage('audio') → orchestrator.setSceneGenerating('audio') → setGenerating() → FAILS (WAITING_CHUNKS → GENERATING invalid) → stale-phase recovery: → deleteState (только WAITING_CHUNKS/GENERATING/FAILED — НЕ DONE) → initPlaceholderReady → setGenerating ✅ → dispatch to GPU (свежая генерация)
✅ Все 4 сценария работают в текущем коде

DONE guard, stale-phase recovery, version gate — всё реализовано в scene-orchestrator.js и orchestrator.js.
