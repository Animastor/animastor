## 9. Versioning / release policy (documented, not changed)

- **Package version** = `animastor-worker` version in
  `worker/worker/package.json` — currently **2.1.0**. This is the canonical
  worker bundle version: the hub publishes it with the artifact
  (`GET /worker-bundle`, setup contract `worker_bundle.version`), the
  installer compatibility resolver compares it against manifest
  `worker_bundle.min_version`, and `worker.cjs` reports it in beacons.
- **Protocol version** = `PROTOCOL_VERSION = 2` inside the canonical
  `contracts/src/job-protocol-v2.js` (mirrored byte-exactly into the bundle
  copy). Owned by `@animastor/contracts`, NOT by the worker package.
- **Next worker patch** (2.1.x): bug fixes with identical bundle file set
  and unchanged wire behavior.
- **Next worker minor** (2.x.0): new env vars, new optional files in the
  bundle, additive worker-side capabilities (hub still accepts old workers).
- **Next worker major** (3.0.0): dropping Node < 18, dropping/removing
  delivery channels, or any change that breaks compatibility with already
  deployed workers/installers.
- **Job Protocol version bump** (2 → 3) is required for ANY wire-semantics
  change: message shapes, `job_id` grammar, auth handshake, Redis keys/TTL,
  timeout/retry/cancel semantics, payload format. Protocol and package
  versions are independent axes; a protocol bump always implies a worker
  release review across hub + backend + worker.
