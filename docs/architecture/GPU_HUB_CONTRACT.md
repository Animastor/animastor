## 4. Authentication planes

### 4.1 Backend plane — `x-api-key`

`[NORMATIVE — FROZEN]`

- Header only — the key is NEVER accepted via query string or body (T9).
- `POST /task` and `DELETE /queue/clear` are gated by `requireApiKey`.
- FAIL CLOSED: `GPU_HUB_API_KEY` unset → `503 {"error":"hub_api_key_not_configured"}`
  — unless `GPU_HUB_ALLOW_OPEN=1` (explicit dev-only opt-out).
- Key mismatch → `401 {"error":"unauthorized"}`.

### 4.2 Worker plane — Bearer credential

`[NORMATIVE — FROZEN]` (PW-4, fail-closed)

- `Authorization: Bearer <token>` header only. Tokens in query/body are never
  consulted; `worker`/`type` query params on `/task/next` are labels validated
  against the credential-derived identity, never identity themselves.
- Token grammar: `wrk.<worker_id_b64url>.<secret_b64url>` (§5).
- Identity resolution: hub hget `animastor:worker-auth` by `sha256(secret)`
  → mirror value `{ worker_id, workspace_id, worker_type, mode, name,
  share_policy }` (§8.6). The hub cross-checks the mirror's `worker_id`
  against the token's self-locator.
- FAIL CLOSED on: missing header (`401 worker_authentication_failed`),
  malformed token / unknown hash / corrupt mirror JSON / worker_id mismatch /
  missing worker_type / non-system mode without workspace
  (`401 invalid_worker_credential`). There is NO uncredentialed lane — a
  missing credential never becomes SYSTEM or SHARE.

### 4.3 Hub → backend callbacks

`[CURRENT BEHAVIOR]` The hub attaches `x-api-key: <GPU_HUB_API_KEY>` to
`POST ${BACKEND_URL}/gpu/task/result` and `POST ${BACKEND_URL}/gpu/task/error`
when the key is configured. The backend's `requireHubCallbackAuth`
(generation-routes.cjs:50-56) is asymmetric: when the backend key is UNSET the
callback hop stays open (legacy behavior); when set, mismatch → 401. Forwarded
`worker_id`/`workspace_id` fields are AUDIT-ONLY — the backend re-verifies
job→book→workspace itself and never trusts them.

`[KNOWN LIMITATION]` The two fail-closed postures differ (hub: 503 when unset;
backend callback: open when unset). Recorded, not changed in 10A.

## 5. Worker token contract

`[NORMATIVE — FROZEN]` Wire format — MUST NOT change:

```
token        = "wrk" "." worker_id_b64url "." secret_b64url
worker_id    = UUID v4 (lowercase/uppercase hex accepted by the regex)
secret       = 32 random bytes (issuer-side; TOKEN_SECRET_BYTES)
```

- Canonical owner (grammar + issuance): backend
  `worker-repo.js` — `generateCredential` (issues one-time plaintext token),
  `parseToken` (parses `{workerId, secretHash}`). PG stores ONLY
  `token_hash` = `sha256(secret)` hex + `token_prefix` display mask
  (`wrk_<8 chars of b64url(secret)>`).
- Hub consumer copy: `gpu-hub.js` `parseWorkerToken` — hand-synced
  implementation of the same grammar (Phase 10A adds a behavioral parity
  guard: both implementations must produce identical `{workerId, secretHash}`
  / null outcomes on a fixture matrix).
- `b64url` = standard base64 with `+→-`, `/→_`, `=` padding stripped.
  Parsing is tolerant of standard-base64 input (decoder maps back).
- The hub NEVER resolves identity from query/body and NEVER sees the
  plaintext secret on the worker side — only the SHA-256 digest is in Redis.
- Consumers treat the token as opaque: worker (`ANIMASTOR_WORKER_TOKEN`
  env), frontend (type only), installer (interactive hidden input; never
  logged, never stored, never passed via argv).

`[CURRENT BEHAVIOR]` Any parse failure (wrong prefix, wrong segment count,
empty secret, non-UUID self-locator, non-string input) yields `null` — the
caller answers 401. It never throws.

`[KNOWN LIMITATION]` Canonical ownership of the GRAMMAR lives in
`worker-repo.js` (backend) while the hub carries a hand-synced copy. Moving
the grammar helper into `@animastor/contracts` is a recorded NEXT STEP — it
would expand the contracts package beyond the frozen Job Protocol v2 scope
(the §14 Docker seam is resolved since Phase 10B; the scope decision is the
remaining gate, not the seam).

## 6. Artifact endpoints (Setup Contract delivery surface)

`[NORMATIVE — FROZEN]` All artifact endpoints are secret-free and
unauthenticated by design: no Worker Key, no `.env` (the
`isServableBundleFile` filter never serves `.env` / `.env.*` except
`.env.example`). Every artifact publishes a sha256. Signatures are
`signature: null` — a future extension.

### 6.1 GET /worker-source — DEPRECATED

- Serves the single file at `WORKER_SOURCE_PATH`
  (default `/app/worker-source/worker.cjs`, compose-mounted read-only from
  `worker/worker/worker.cjs`) as
  `application/javascript; charset=utf-8`, attachment `worker.cjs`,
  `Cache-Control: no-store`, `Deprecation: true`,
  `Link: </worker-bundle>; rel="successor-version"`.
- File missing → `404 {"error":"worker_source_unavailable"}`.

### 6.2 GET /worker-bundle

- Full worker runtime bundle (tar.gz) built from `WORKER_BUNDLE_DIR`
  (default `/app/worker-bundle`, mounted from `worker/worker`).
- Entries are prefixed `animastor-worker/<relpath>` — the installer engine
  depends on this prefix (worker.js:251).
- Deterministic: fingerprint cache (sorted relpath + size + mtime of every
  included file); rebuilt only when the source tree changes.
- Headers: `Content-Type: application/gzip`,
  `Content-Disposition: attachment; filename="<name>-<version>.tar.gz"`,
  `Cache-Control: no-store`, `X-Animastor-Artifact-Version: <version>`,
  `X-Animastor-Sha256: <hex>`.
- Version read from the canonical `WORKER_BUNDLE_DIR/package.json`
  (`animastor-worker`); no canonical version or no files →
  `404 {"error":"worker_bundle_unavailable"}` (never a versionless artifact).

### 6.3 GET /worker-bundle/sha256

- `200 {"artifact":"worker-bundle","version":<semver>,"sha256":<hex>,"bytes":<n>,"files":[...],"signature":null}`
- Same availability rule → `404 worker_bundle_unavailable`.

### 6.4 GET /workflow/:id

- `<id>` must match `WORKFLOW_ID_RE = /^[a-z0-9][a-z0-9._-]*$/i`; the
  allowlist is derived from the canonical install manifests
  (`INSTALLER_MANIFESTS_DIR/**.json` → `workflows.artifacts[]`, id without
  the `workflow:` prefix). Legacy/excluded workflow files are never served.
- Path traversal defense: resolved path must stay inside `WORKFLOW_DIR`.
- `200` JSON body, `Content-Disposition: attachment; filename="<filename>"`,
  `Cache-Control: no-store`, `X-Animastor-Sha256`.
- `404 {"error":"workflow_not_found"}` (bad id / not allowlisted / traversal)
  or `404 {"error":"workflow_unavailable"}` (file unreadable).

### 6.5 GET /installer (bootstrap launcher)

- Query params (all optional, fail-closed):
  `?profile=<comma-ids>` — every id must be in the manifest profile
  allowlist (hidden/internal profiles never embeddable) else
  `400 {"error":"invalid_profile"}`;
  `?mode=<m>` ∈ {managed, existing, shared, isolated} else
  `400 {"error":"invalid_mode"}`;
  `?platform=<p>` ∈ {linux, windows} else `400 {"error":"invalid_platform"}`;
  without the param a Windows User-Agent gets the PowerShell launcher.
- Embeds the public hub URL: `config.PUBLIC_HUB_URL` if set; else a clean
  DNS-name `Host` header → `https://<host>/gpu`; else
  `https://animastor.in/gpu`.
- `200` bash (`text/x-shellscript`, `animastor-installer.sh`) or PowerShell
  (`text/plain`, `animastor-installer.ps1`) launcher;
  `Cache-Control: no-store`, `X-Animastor-Bootstrap-Version: <BOOTSTRAP_VERSION>`,
  `X-Animastor-Artifact-Version: <installer version>`.
- Installer version from canonical `INSTALLER_SRC_DIR/package.json`; missing
  → `404 {"error":"installer_unavailable"}`.
- The launcher downloads `/installer/bundle`, verifies sha256 against
  `/installer/sha256`, unpacks and runs the installer CLI. The Worker Key is
  NEVER part of this exchange (asked interactively on the GPU machine).

### 6.6 GET /installer/bundle and /installer/sha256

- Self-contained tar.gz with layout `animastor-installer/…`:
  `src/installer/*`, `ai/install-manifests/*`, `backend/ai/workflows/*`,
  `worker/worker/*` (bundle files), generated `package.json` + `README.txt`.
- `/bundle` → same header set as §6.2 (installer version);
  `/sha256` → `{"artifact":"installer","version",…,"signature":null}`.
- `404 {"error":"installer_unavailable"}` when no canonical version.

## 8. Redis contracts

`[NORMATIVE — FROZEN]` Redis usage is data-structure only (hash / list /
string with TTL / SCAN / HSCAN) — NO pub/sub, no keyspace notifications, no
server-side modules. Ownership is defined by the machine-enforced registry
`backend/tests/architecture/redis-registry.js`; every `animastor:*` literal
in backend src and gpu-hub must belong to a registered family
(redis-ownership.test.js). Phase 10A does NOT move ownership.

### 8.1 Hub-owned families (author: gpu-hub)

| Family | Type | Semantics |
|---|---|---|
| `animastor:queue:{type}` | list | System pool lanes (type ∈ audio/image/video). LPUSH on enqueue (RPUSH on filtered re-keep), RPOPLPUSH source on pop. |
| `animastor:queue:{type}:ws:{workspace_id}` | list | Workspace lanes (PW-2). Key derived from SERVER data only. |
| `animastor:queue:{type}:policy:{policy_id}` | list | SH-2 users-policy lanes. Derived from the credential-resolved policy, never client input. |
| `animastor:processing` | list | In-flight lane (RPOPLPUSH destination on claim; LREM on completion). Orphan sweep reader. |
| `animastor:running` | hash | `job_id` → running-record JSON (worker, workspace_id, worker_mode, worker_workspace_id, worker_share_policy, job_type, params, assets, build_id, book/chapter/scene/stage, dispatch_id, timeout_ms, protocol_version, worker_version, worker_image_tag, worker_protocol_version, task_raw, started_at). |
| `animastor:processing-claimed` | hash | `job_id` → `{first_seen}` orphan-sweep bookkeeping. |
| `animastor:dead-letter` | list (TTL 7d) | Poison / requeue-limit entries `{reason, ts, entry}` — kept for audit, never requeued. |
| `animastor:job:{dispatch_id}:{job_id}` | string (TTL 3600) | Enqueue dedup, `SET NX EX`. BEST-EFFORT only — the authoritative result dedup is backend-side (`animastor:result-processed:*`). Backend deliberately DELs keys before legitimate re-dispatch (frozen debt, §8.7). |

## 9. Worker ↔ Hub flow

`[NORMATIVE — FROZEN]`

1. **Register** — `POST /beacon`, Bearer. Body labels only:
   `{id?, type?, gpu, vram, version, image_tag, protocol_version}`.
   Identity + type come from the credential (mirror). `409
   protocol_version_mismatch {error, expected, received}` on version != 2.
   Side effects: registry entry + heartbeat idle stamp. `200 {ok:true}`.
2. **Poll** — `GET /task/next?type=<type>`, Bearer. Mode-scoped pop
   (private → own ws lane; share/system → system pool; kill-switch-gated
   borrow step for public/users policies). Poison-write lane cross-check on
   pop. Empty → `200 {task:null}`; claimed → `200 {task:{...envelope}}`
   (task body exactly as enqueued by /task — the hub adds nothing).
   Claim is bound to the authenticated worker + workspace; running record
   + processing entry written atomically-enough for the orphan sweep.
   Status codes: 401 (no/invalid credential), 404 `not registered`
   (no beacon yet), 409 `worker_protocol_mismatch` / `worker_type_mismatch`.
3. **Complete** — `POST /task/result`, Bearer, claimer-only.
   `{job_id, build_id, result_base64, dispatch_id, protocol_version}`.
   400 `invalid` (missing/shape), 409 `stale_or_unknown_dispatch`,
   403 `not_task_claimer`. Result key written first (TTL 1h), then backend
   forward (5 retries × 500 ms). `200 {ok:true}` EVEN when backend delivery
   failed after retries (the result key is the recovery path).
4. **Fail** — `POST /task/error`, Bearer, claimer-only.
   `{job_id, build_id, dispatch_id, protocol_version, reason}`.
   Same status semantics; clears running/processing/dedup and re-stamps an
   idle heartbeat; forwards to backend (5 retries; fallback
   `animastor:error:{job_id}` TTL 1h). `200 {ok:true}`.

`[CURRENT BEHAVIOR]` The worker polls in a loop with backoff; `401/403`
triggers the worker's authFailed gate (no silent downgrade). Mixed-version
rollout is NOT supported — all three components reject a mismatching
`protocol_version`.

## 10. Backend ↔ Hub flow

`[NORMATIVE — FROZEN]`

1. **Dispatch** — `POST /task` (x-api-key), body:
   `{job_id, params, job_type, assets, build_id, protocol_version, dispatch_id,
   book_id, chapter_id, scene_id, stage, workspace_id?, timeout_ms?, policy_id?}`.
   `workspace_id` / `policy_id` are BACKEND-AUTHORED (book → workspace →
   private-worker / grant-lane resolution); client-supplied values are
   overwritten by the dispatcher. Validation and queue routing per §3/§8.1.
   Dispatcher sends with 3 attempts × 30 s timeout (gpu-dispatcher.js).
   Hub responses: `200 {ok:true}` | `200 {ok:true, duplicate:true}` |
   409/400/401/503 per §11.
2. **Complete callback** — hub → `POST ${BACKEND_URL}/gpu/task/result`
   (x-api-key when configured). Body adds audit-only `worker_id`,
   `workspace_id` to the worker's payload. Backend re-verifies ownership.
3. **Error callback** — hub → `POST ${BACKEND_URL}/gpu/task/error`
   (notifyBackendError: 5 retries × 500 ms → fallback Redis key). Reasons:
   worker-supplied reason, `worker_timeout`, `orphaned_task`.
4. **Cancel/cleanup** — `DELETE /queue/clear` (§8.5).
5. **Setup contract** — backend probes `GET /worker-bundle/sha256` and
   `GET /installer/sha256`; installer engine downloads `/worker-bundle`
   (sha256-verified), `/workflow/:id`, `/worker-source` (fallback).

## 13. Timeout / retry / cancel semantics

`[NORMATIVE — FROZEN]` Division of responsibility: the hub is a dumb
transport; the backend owns retry/re-dispatch policy (dispatch-lease expiry).
The hub never re-dispatches a job on its own except the orphan requeue below.

- **Per-job timeout:** `timeout_ms` from /task, floored at
  `max(Number(timeout_ms), GPU_TIMEOUT_MS)` when positive, else default
  `GPU_TIMEOUT_MS`. Enforced by the 10 s sweep.
- **Per-GPU timeout:** registry `last_seen` older than `GPU_TIMEOUT_MS` →
  registry entry deleted; that worker's still-running jobs reported
  `worker_timeout`.
- **Timeout cleanup order:** running hdel → processing LREM → claimed hdel →
  dedup DEL (frees re-dispatch) → `notifyBackendError("worker_timeout")`.
- **Orphan sweep:** processing entries with no running record requeue to
  THEIR OWN lane after `ORPHAN_GRACE_MS` (crash between RPOPLPUSH and the
  running write); `orphan_requeues` counter stamped into the task body;
  beyond `MAX_ORPHAN_REQUEUES` → dead-letter + `orphaned_task` to backend.
  Poison entries (unparseable / lane-mismatch on pop) → dead-letter, never
  requeued.
- **Backend delivery retries:** 5 attempts × 500 ms for both callbacks;
  ERROR additionally falls back to `animastor:error:{job_id}` (TTL 1h);
  RESULT needs no fallback (the result key already holds the payload).
- **Dedup release:** on `/task/error` and timeout paths the hub DELs
  `animastor:job:{dispatch}:{job}` so the backend re-dispatch is not rejected
  as duplicate; on `/task/result` the dedup key is left to expire (1 h).

`@animastor/contracts` (`contracts/src/job-protocol-v2.js`; normative doc
docs/architecture/JOB_PROTOCOL_V2.md). The hub:
